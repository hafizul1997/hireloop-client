# HireLoop

Job/recruitment application built on Next.js 16 (App Router, `src/` directory) with TypeScript, Tailwind CSS v4, shadcn/ui (Base UI), and MongoDB + Better Auth for authentication. The public shell, auth stack, and all three role dashboards (seeker / employer / admin) are implemented with live MongoDB reads/writes; the public marketing pages (`/jobs`, `/company`, `/pricing`) and a real payment provider are still missing.

## Commands

```bash
npm run dev     # Start dev server (Turbopack) at http://localhost:3000
npm run build   # Production build
npm run start   # Serve production build
npm run lint    # ESLint (eslint-config-next core-web-vitals + typescript)
```

There is no test suite or formatting script (no Prettier) configured yet.

## Tech stack

- **Next.js 16.4.5** — App Router only, `src/app/` structure. React Compiler is enabled (`reactCompiler: true` in `next.config.ts`) — do not add manual `memo`/`useCallback` optimizations unless profiling shows a need.
- **React 19.3** with `react-jsx` transform (no manual `import React`).
- **Tailwind CSS v4** via `@tailwindcss/turbopack` (CSS-first config in `src/app/globals.css`; no `tailwind.config` file). `tw-animate-css` available. The loader is also wired explicitly in `next.config.ts` under `turbopack.rules`.
- **shadcn/ui via Base UI** (`@base-ui/react`, style `base-nova`) — components in `src/components/ui/`, added with `npx shadcn`. Icons: `lucide-react`. Class helper: `cn` from `@/lib/utils`.
- **Better Auth 1.7** with the MongoDB adapter (`@better-auth/mongo-adapter`, `mongodb` driver v7). Email/password + Google social provider.
- **TypeScript strict** mode, `@/*` path alias → `./src/*`.

## Key files

- `src/lib/db.ts` — shared MongoDB client (same Atlas cluster as the Express backend in `d:\hireloop-server`, database **`hireloop`** — changed from `hireloopdb`, so pre-existing test accounts must re-register). Exports `client`/`db` plus typed collections: `users` (Better Auth–managed `user` collection), `jobs`, `applications`, `savedJobs`, `activities`, `transactions` (demo billing ledger — `TransactionDoc`: email, company, plan, txnId, amount, `success|pending|failed` status; no server action writes these yet, they are seeded/demo data), `profiles` (per-user professional profile — `ProfileDoc`: headline, bio, skills, plus an inline base64 `resume` file ≤2MB), plus the Better Auth `accounts`/`sessions` collections (only touched by admin user-moderation actions). Also exports the `APPLICATION_STATUSES` list and an `objectId()` string→ObjectId helper (Better Auth's adapter stores ObjectId `_id`s but exposes string `id`s).
- `src/lib/guards.ts` — `requireUser()` / `requireRole(role)`: session guards that redirect to `/sign-in` or the role home; `requireUser()` force-signs out and redirects suspended users (`status: "suspended"`) to `/sign-in?suspended=1`. Used by every dashboard page and server action.
- `src/lib/format.ts` — `timeAgo()` relative dates and `statusLabel()` for status pills.
- `src/lib/growth.ts` — `growthPercent(current, previous)` for the stat-card delta badges (`null` → em dash when the baseline is 0).
- `src/hooks/use-mobile.ts` — `useIsMobile()` matchMedia hook (`<768px`).
- `src/app/dashboard/actions.ts` — `"use server"` mutations (`saveJob`, `unsaveJob`, `applyToJob`, `postJob`, `employerUpdateJob`, `toggleJobStatus`, `updateApplicationStatus`, `adminUpdateJob`, `adminCreateJob`, `adminDeleteJob`, `adminCloseJob`); each re-checks the role, scopes writes to the caller's id (ownership checks on employer/admin writes; `adminDeleteJob` cascades the job's applications and saves), writes `activities` feed entries for both sides of an event, and revalidates the dashboard paths. Admin user moderation mutations (`updateUserRole`, `updateUserStatus`, `deleteUser` — cascades sessions/accounts/user/jobs/applications/saves/activities, blocks admins and self-edits) live separately in `src/app/dashboard/admin/users/actions.ts`.
- `src/lib/auth.ts` — server-side Better Auth instance (MongoDB adapter via `src/lib/db.ts`).
- `src/lib/auth-client.ts` — client-side auth helpers (`better-auth/react`), created as `createAuthClient<typeof auth>()` for type inference; exports `authClient` plus `signIn`/`signUp`/`signOut`/`useSession` from the single configured client (same-origin default).
- `src/app/api/auth/[...all]/route.ts` — catch-all route handler mounting Better Auth (`toNextJsHandler`); exposes `/api/auth/*` (sign-in, sign-up, session, etc.).
- `src/app/api/**/export/route.ts` — four CSV export handlers (`GET`, `text/csv` + `Content-Disposition` attachment, quote-escaped, capped at 1000 rows): `admin/transactions/export` and `admin/users/export` (admin-only, 403 otherwise; honor `?status=` / `?q=`+`?role=` via the same filter builders the pages use — `buildTxnFilter` from `dashboard/admin/payments/tiers.ts`, `buildUserFilter` from `dashboard/admin/users/filter.ts`) and `dashboard/applications/export` + `dashboard/billing/export` (any signed-in user, scoped to the caller's own data; 401 otherwise). Also `dashboard/resume/route.ts` — `GET` downloads the caller's stored resume, `POST` replaces it (multipart `file` field, PDF/DOC/DOCX ≤2MB validated server-side; a route handler because resumes exceed the 1MB server-action body cap).
- `src/components/site-navbar.tsx` — `SiteNavbar` header (dark theme, branded Logo, links to `/jobs`, `/company`, `/pricing`). Async server component: reads the session — logged-out users get Sign In / Get Started CTAs, logged-in users get a "Go to Dashboard" button linking to their role home. Rendered by the `(site)` group layout only (not the dashboard).
- `src/app/globals.css` — Tailwind v4 + shadcn design tokens/CSS variables (includes `@import "shadcn/tailwind.css"` and sidebar/chart token mappings).
- `src/app/dashboard/` — authenticated, full-bleed portal. `layout.tsx` guards the session, mounts the shadcn `SidebarProvider` (with `dark` class + sidebar token overrides for the #0a0a0a palette), `components/sidebar.tsx` (`DashboardSidebar` built on `@/components/ui/sidebar` primitives, `collapsible="icon"`, `SidebarTrigger` toggle in `components/topbar.tsx`, mobile Sheet drawer), a `Topbar` whose left side holds the sidebar toggle + a Home link back to `/`, plus `fab.tsx` and shared `components/`: `job-post-form.tsx` (client editor matching the "Post a New Job" design — three numbered sections with descriptions: 1. Basic Information (title/company, category, segmented Job Type pills) / 2. Location, Compensation & Timeline (remote-work toggle, location, deadline, min/max salary + frequency, work mode, industry) / 3. Responsibilities & Required Skills; driven by a passed server action) — `postJob` / `employerUpdateJob` / `adminUpdateJob` all parse it via a shared `parseJobForm` (optional fields stored with `withoutUndefined`, composed `salary` string for display). `stat-card.tsx` (icon-tile stat: icon top, muted label, big value), `recent-activity.tsx` (maps `ActivityKind` → icon), `recent-applications.tsx` (employer "Recent Applications" table — candidate initials/role/date/status pills, plain `ApplicationRow[]` props), `job-posts-table.tsx` ("Manage Job Posts" table for the employer — title/dept, company/location, type pill, compensation, applicant counts, Active/Expired pill, deadline + posted, Update link / confirmed delete via `employerDeleteJob` / kebab `RowMenu` with open-close + View Applicants), `row-menu.tsx` (`RowMenu` details/summary popover closing on outside click/Escape), `confirm-submit.tsx` (shared `ConfirmSubmit` confirm-dialog submit button — moved out of `admin/users/components/user-controls.tsx`), `status-badge.tsx`, `job-card.tsx` (also exports `Crumb`/`EmptyState`/`PageHeader`/button style constants — `BTN_PRIMARY`/`BTN_SECONDARY`/`BTN_DONE` — reused across pages), `plan-card.tsx` (static billing display), `profile-settings.tsx` (shared three-card settings layout — `settings/profile-information.tsx` avatar upload + name/password via `authClient.updateUser`/`changePassword`, `settings/resume-card.tsx` upload/replace/remove, `settings/professional-details.tsx` headline/bio/skill-chips), `coming-soon.tsx`. Per-role shared components live in sub-folders: `admin/components/overview.tsx` (`OverviewStatCard`, `TransactionsTable`), `admin/users/components/user-controls.tsx` (`RoleFilter`), `admin/jobs/components/job-filters.tsx` (`StatusFilter`, `CategoryFilter`), `admin/payments/components/txn-controls.tsx` (`TxnStatusFilter`), `saved-jobs/components/sort-select.tsx` (`SortSelect`). `data.ts` is the per-role content source for sidebar nav, the user-card role label ("Job Seeker"/"Recruiter"/"Administrator") + settings link, CTA, and a static sample activity feed used as fallback while a user has no DB activity. Every page below is server-rendered with live MongoDB queries and a role guard:
  - Seeker (`page.tsx`, guarded `employee`): live stats (saved/applied/interviews/offers counts), `jobs/` (browse + save/apply forms), `saved-jobs/` (sortable via `SortSelect`), `applications/` (status pills) with `applications/[applicationId]/` detail page (ownership-checked fetch, fact cards + job details if the job still exists), `billing/` (plan card + demo card + live `transactions` history with `?q=` search and CSV download link), `settings/`.
  - Employer (`employer/page.tsx`, guarded `employer`): "Welcome back" + 4 live stats (total job posts / total applicants / active / closed) + `RecentApplications` table (last 5, status pills), sidebar **Add Job** → `employer/jobs/new/` ("Post a New Job" header + Back to All), `employer/jobs/` ("Manage Job Posts" — `JobPostsTable` with Update/kebab/delete per row), `employer/jobs/[jobId]/edit/` (sectioned editor, ownership-checked), `employer/applicants/` (status dropdown → writes + notifies seeker), `employer/billing/` (static `PlanCard`, not in the sidebar nav), `employer/settings/`.
  - Admin (`admin/page.tsx`, guarded `admin`): platform stats (users, active jobs, employers, sign-ups today) + merged live feed + last-5 `TransactionsTable`, `admin/users/` (directory with role/status filters → `updateUserRole`/`updateUserStatus`/`deleteUser` actions), `admin/jobs/` (moderate: close/Edit links, status/category filters) with `admin/jobs/new/` (create listing via `adminCreateJob`) and `admin/jobs/[jobId]/edit/` (same editor, any listing; `adminDeleteJob` from the edit page), `admin/payments/` (revenue stat cards with `growthPercent` deltas, subscriber counts, tier pills, transaction ledger filtered by `?status=` via `payments/tiers.ts`), `admin/reports/` (static placeholder), `admin/settings/`.
  - `[...rest]/page.tsx` remains as the "coming soon" catch-all for any other `/dashboard/*` path. The root layout does NOT render `SiteNavbar`; it is mounted only by the `src/app/(site)/` route group layout that wraps the public pages (`page.tsx`, `sign-in`, `sign-up`, `auth/redirect`).
- `src/components/ui/*` — shadcn-style components (`button.tsx`, `input.tsx`, `sonner.tsx` toaster wrapper, plus `sheet.tsx`, `sidebar.tsx`, `tooltip.tsx`, `skeleton.tsx`, `separator.tsx` used by the dashboard shell). `src/components/logo.tsx` holds the shared `Logo` (used by navbar + auth pages); `src/components/auth/` holds the sign-in/sign-up forms plus a shared `auth-shell.tsx` layout.
- `scripts/` — standalone Node scripts (run with `node`, no npm script): `seed-db.mjs` (idempotent demo data: employer + 7 jobs + applications/saves/activities, scrypt password hash) and `migrate-db.mjs` (one-time copy of Better Auth collections from the old `hireloopdb` database to `hireloop`).
- `components.json` — shadcn config (`base-nova` style, `neutral` base color, lucide icons).

The only navbar routes still missing are `/company` and `/pricing`. `/jobs` is the public job board (`src/app/(site)/jobs/`): light content zone on the dark site — search bar (`?q=`, inline server action redirect), white Filters sidebar (Job Type checkboxes with live counts, `?type=` comma list, auto-navigating client `jobs-controls.tsx`), "Found N Professional jobs" + `SortSelect` (`?sort=`), dark `JobBrowseCard` listings (`src/components/job-browse-card.tsx` — logo tile, tags, bookmark: save/unsave via `saveJob`/`unsaveJob` for seekers, sign-in link for guests, hidden for employer/admin), and server-rendered pagination (`?page=`, 6 per page, ellipsized window). `/sign-in` and `/sign-up` exist (`src/app/(site)/sign-in/page.tsx`, `src/app/(site)/sign-up/page.tsx`, rendering client forms from `src/components/auth/`): email/password auth, Google OAuth (which lands on `/auth/redirect` to resolve the session first), and a three-role picker on sign-up (employee/employer/admin, stored as `role` via Better Auth `user.additionalFields`, default `employee`; a read-only `status` field `"active" | "suspended"` is admin-managed only). After auth, users are redirected by role via `getRoleHome` in `src/lib/role-redirect.ts`: employee → `/dashboard`, employer → `/dashboard/employer`, admin → `/dashboard/admin`. Each dashboard page re-checks the session role server-side and redirects mismatches to their role home. Logout lives in the dashboard sidebar (`authClient.signOut`); errors/successes across auth flows use sonner toasts (`Toaster` from `src/components/ui/sonner.tsx`, mounted in the root layout). `src/app/(site)/page.tsx` renders `Hero` from `src/components/hero.tsx` (badge, headline, job search form linking to `/jobs`, popular-search tags, planet-glow backdrop, and a stats strip).

## Environment variables

`.env` (do not commit real secrets):

- `MONGODB_URI` — MongoDB connection string (required by `src/lib/auth.ts`).
- `BETTER_AUTH_SECRET` — auth signing secret.
- `BETTER_AUTH_URL` — auth base URL (e.g. `http://localhost:3000` in dev).
- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — referenced by `src/lib/auth.ts`; keys exist in `.env` but are empty until real Google OAuth credentials are added (Google sign-in fails at request time until then; email/password works regardless).

## Conventions

- App Router with the `src/` directory; route handlers live under `src/app/api/**/route.ts`.
- Classic `"use client"` boundaries are decided per file; prefer server components by default, client components only where hooks/interactivity are needed.
- Use `@/` alias for all internal imports.
- shadcn/ui primitives come from `@/components/ui/*`; don't hand-roll equivalents.
- Fonts: Geist + Geist Mono loaded via `next/font/google` in `src/app/layout.tsx` — reuse the `--font-geist-sans`/`--font-geist-mono` CSS variables (`font-sans`, `font-mono`).
- Database access flows through the shared `MongoClient` in `src/lib/db.ts` — never open a new client per call; route handlers and pages import `db` (or the typed collections) from there.
